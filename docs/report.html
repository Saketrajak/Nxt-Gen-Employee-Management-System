1. Engineering Assumptions (Mandatory Declaration)

In accordance with the assessment instructions permitting reasonable assumptions, the following foundational architectural assumptions were established at the inception of the solution:

  1. Employee Code Generation & Immutability: The alphanumeric Employee Code (e.g., I0001, H0001) reflects an employee’s active departmental assignment. It remains strictly immutable during routine profile edits and is only altered upon the execution of an authorized Department Transfer, upon which a new sequential code is automatically allocated.
  2. Internal Primary Key Preservation: For database referential integrity and audit compliance, the internal database primary key (id BIGINT) never changes throughout an employee’s organizational lifecycle. All past historical audit records, transfer logs, and system references remain linked to this surrogate key.
  3. Sensitive Identity Data Privacy: In strict alignment with Requirement Task B.5, Aadhaar numbers and PAN are deliberately excluded from unrestricted global text search to prevent inadvertent identification data leakage. Furthermore, Aadhaar digits are masked in the UI (XXXX-XXXX-1234) with role-restricted unmask toggles.
  4. Department Sequence Concurrency Control: To eliminate race conditions under concurrent employee onboarding or simultaneous department transfers, sequence increments are managed using Pessimistic Row-Level Locking (SELECT ... FOR UPDATE), ensuring zero duplicate code generation.
  5. Statutory Currency & Compensation Standards: All financial compensation figures are modeled in Indian Rupees (INR ₹) with predefined Lakhs Per Annum (LPA) filtering bands (₹1–3 LPA, ₹3–5 LPA, ₹5–10 LPA, ₹10+ LPA, and custom).

4.2 Technical Concurrency & Transaction Implementation

  • Atomic Code Generation Service: Uses @Lock(LockModeType.PESSIMISTIC_WRITE) to acquire an exclusive lock on the departmental sequence row during increment operations. This guarantees zero duplicate codes even under simultaneous requests.
  • Department Transfer Engine: Enclosed within @Transactional(rollbackFor = Exception.class). If code generation, employee update, or audit logging encounters an exception, the entire transaction is rolled back, preventing orphaned or corrupt state.
  • Statutory Validations: Enforced through Jakarta Bean Validation (@Pattern for 10-digit mobile and PAN format ABCDE1234F, @DecimalMin for positive salary, and @Past for Date of Birth).

5. Frontend Web Application (Task A)

The client is built using React 19 with Vite and Tailwind CSS, styled with a professional military/defense palette (slate, navy, and emerald accents):

5.1 Core Frontend Features

  1. Employee Management Directory Table: Displays Employee Code, Full Name, Department, Role, Contact, Annual Salary (INR formatted), Status badge, and contextual action buttons. Supports multi-column ascending/descending sorting and server-side pagination with 5, 10, and 20 rows per page.
  2. Reactive Aadhaar Input Auto-Formatting: Automatically injects hyphens into the Aadhaar input field as the user types (XXXX-XXXX-XXXX) and caps at exactly 12 numeric digits with immediate visual feedback.
  3. Statutory PAN Card Validator: Enforces uppercase format conversion and regex validation ([A-Z]{5}[0-9]{4}[A-Z]{1}) in real time before submission.
  4. Combined Global Search & Multi-Filter Drawer: Debounced global search across permitted text fields combined with simultaneous filters for Department, Role, Status, Gender, Joining Date, and Salary LPA presets (₹1–3 LPA, ₹3–5 LPA, ₹5–10 LPA, ₹10+ LPA, or custom Min/Max).
  5. Department Transfer Modal: Displays employee details, disables reassignment to current department, dynamically queries the API to display the projected new code, and collects an official transfer justification.
  6. Personnel 360° Profile Dossier: Modal displaying personal, identity, and employment records with an interactive Aadhaar masking toggle (XXXX-XXXX-1234) and a chronological transfer audit timeline.
